# 长 PDF 阅读与双语导出

2026 年 11 月 22 日，Windows、Edge 158.0.4370.33。首屏时延和交互使用真实扩展、PDF.js、Canvas、IndexedDB 与浏览器下载。文字翻译采用延迟 60 ms 的固定本地 HTTP Provider。扫描页采用随扩展分发的 Tesseract WASM 和本地权重。

## 长文档首屏

初始工作树基于 `371ede6`。原阅读器需要 PDF 地址，依次提取全书文本、统计重复页眉页脚、聚类并创建每页画布后，才开始绘制第一页。普通用户无法从弹窗选择一个本地文件，也无法从阅读器导出自己已读的双语段落。

新阅读器先绘制第一页。重复页眉页脚使用固定的前三页样本，样本读取失败可重试，其余页继续工作。页面每 16 页一组，先创建占位，再为临近视口或主动跳转到的组创建页节点。文本提取和翻译优先处理当前页，原文绘制和 Provider 请求使用独立的并发槽。长页的译段按批次出现。

### 同文件、同入口的三组对照

夹具为自制的 180 页文档，含目录、跨页章节、双栏、表格和纯图像扫描页。文件大小 724,384 字节，SHA-256 为 `dcd76739f7b41ae289dae379c10512bed4ee30a281e7877aafe600051ec8b4cf`。早期预实验使用了 724,428 字节的无目录版本，下表只列带目录版本的交替测试。每轮先跑初始构建，再跑改后构建。

为保证入口相同，计时从同一浏览器阅读器地址开始导航，PDF 字节由回环 HTTP 提供。每个冷开使用新 Edge 配置，保留操作系统磁盘缓存。暖开在同一配置内关页后重开，保留扩展翻译缓存及浏览器缓存。视口为 1280×900，设备像素比为 1。首屏原文取动画帧中首次检出第一页画布上的深色不透明文字像素，首段译文取第一页首个译段从等待状态变成固定 Provider 结果的动画帧。请求数在首段译文出现后再等 450 ms 读取，包含邻页预取。

| 条件 | 初始三次（ms） | 改后三次（ms） | 中位数（ms） |
| --- | --- | --- | --- |
| 冷开，第一页原文 | 400 / 369 / 411 | 226 / 271 / 322 | 400 → 271 |
| 冷开，第一页首段译文 | 565 / 527 / 557 | 375 / 433 / 484 | 557 → 433 |
| 暖开，第一页原文 | 352 / 461 / 313 | 211 / 142 / 207 | 352 → 207 |
| 暖开，第一页首段译文 | 422 / 524 / 374 | 291 / 234 / 285 | 422 → 285 |

三轮见字时的页节点数均从 180 降到 1。冷开观察窗口的 Provider 请求由 5 次降到 2 次，暖开两种构建都为 0。以上数字衡量本机阅读器开销与固定响应时延；真实翻译时间还取决于用户配置的服务。三轮测试后微调了桌面分栏的画布顶部对齐；本地文件入口另有端到端验证。

## 阅读、跳页、恢复和导出

1. 点击扩展图标、**阅读本地 PDF**、**打开本地 PDF**，从系统文件选择器中选择文档。浏览器读取该文件的字节。PDF 阅读器使用当前翻译服务。扫描页上的“识别本页”调用用户已选的 OCR 引擎。
2. 查看第一页原文和译段，输入页码后按 Enter 或点**跳转**。第 90 页的双栏样例按左栏五行、右栏五行分成两个正文段。点击**定位原文**会定位并高亮纸面上的文字，点高亮区域会返回对应译段。文字层按段定位，OCR 段可返回对应扫描页。
3. 第 91 页的三列样例逐格保留了表头和两行数据，包括数量 12 和 4。版面识别有误时可在阅读器内切换**本页版式**，重算当前页并留在原页码。第 92 页无文本层，在仅原文模式跳入、切回双语后点**识别本页**，本地 OCR 实际读出 `READ THE SCANNED PAGE`；固定 Provider 的回包进入右侧译段和导出文件。
4. 选择**全文**或**当前页**，点**导出双语 HTML**。导出读取当前会话的快照。测试实际下载并在 Edge 重新打开了包含 180 个页节的 HTML，复核了段落顺序、OCR 内容及未读页标记。已读原文旁的缺失译文标为「尚未翻译」，未识别扫描页另有标记。桌面阅读器显示原 PDF 画布，导出的 HTML 是可离线打开的双语文本，表格按阅读次序列出。本次未实现保留原版式的双语 PDF 下载。

额外验证了三个容易干扰长文档阅读的情形。

- 将页并发设为 1，测试服务一直扣住第一页的翻译响应，跳到第 90 页仍能绘制该页画布并显示对应原文。服务恢复后可以继续翻译。对已提交给服务的请求保留其结果，排队中的页面按当前页优先。
- 页面中途关闭后台 worker 后，阅读器会接收续译记录。如果通道在记录持久化之前关闭，仍在等待的这批段落会再尝试一次。浏览器冒烟测试实际终止、重启 worker 并核对两个已访问页面的译文。
- 第 94 页没有本页标题，真实浏览器发出的请求包含第 93 页的标题。第 96 页的请求取到了第 95 页开始的目录书签 `Trace analysis`，文档标题都是元数据里的 `Systems handbook`。每页优先使用本页短标题，没有可用标题时查找最多 256 个内部书签；仍无匹配就参考紧邻前页的标题。单页提取失败不会妨碍其他页面使用重复页眉样本。

## 真实双栏论文的抽查

- BERT 论文第 1 页的初始聚类把左栏「Abstract」接到了右栏正文。调整后，Edge 本地打开同一 PDF，次序为摘要、左栏引言、右栏正文。摘要的两个正文段定位宽度均约占整页 31%，右栏正文约 37%。作者行被拆成两段，阅读器仍按原论文的姓名次序展示。[ACL Anthology 论文和 PDF](https://aclanthology.org/N19-1423/)
- ResNet 论文第 3 页初始共有 11 段，其中 6 段的定位框宽于整页的 56%，左栏标题曾接入右栏拆词。改后为 17 段，无此类超宽定位框，3、3.1、3.2、3.3 的章节次序正确。3 与 3.1 仍可能在同一译段中。第 6 页的表 3 原来把一个模型的指标 9.15 接到右侧示意图标签；改后自动版式按三个表头、十行各三格输出，末行是 ResNet-152、21.43、5.71。表格预设也通过该检查。[ResNet 论文 PDF](https://arxiv.org/pdf/1512.03385)
- 水平间隙和相邻行数字对齐是启发式。第 6 页下方仍有指标表在自动版式中被合并成较长段落，手选表格版式会进一步分开。合并单元格、复杂图中文本和任意多栏页面尚无逐格正确性的保证。

## 复测

```powershell
npm run typecheck
npx vitest run tests/pdf-reading.test.ts tests/pdfSegment.test.ts tests/pdf-page-lifecycle.test.ts
npm run build
python scripts/fixtures/make-reader-sample.py "$env:TEMP/polypage-reading-sample.pdf" "C:/Windows/Fonts/arial.ttf"
node scripts/pdf-reader-check.mjs "$env:TEMP/polypage-reading-sample.pdf"
npm run smoke
```

生成器需要 ReportLab 和 Pillow。浏览器脚本接受第三个参数指定已构建的扩展目录，第四个参数 `--baseline` 只跑两种构建共有的地址打开路径。例如将一开始的工作树构建另存后，可运行 `node scripts/pdf-reader-check.mjs sample.pdf C:/path/to/initial-dist --baseline`。脚本为每次启动创建临时配置，结束后清理。公开论文可另行下载，在同一个阅读器输入上述页码验证。
